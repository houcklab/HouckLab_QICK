# t1

Class `T1FF` (see `qicklab.experiments.t1`); exponential fit in `qicklab.analysis.fitting`.
Regime **A**.

## What it measures

Energy relaxation time T1: pi pulse, variable wait, readout. The wait is a register sweep
inside one `RAveragerProgram`. Part of the standard per-device coherence benchmark
(T1 / T2R / T2E); see also [t2_ramsey](t2_ramsey.md), [t2_echo](t2_echo.md) and the
combined steps on [coherence_combos](coherence_combos.md).

## Pulse sequence

```
           sync  t=0.01 us
qubit_ch  __|____[ pi: Gauss 4 sigma, pi_gain, phase 90 ]______________________________
PMOD 0    __|__[~~~~~ trig_buffer_start + 4 sigma (+flattop) + trig_buffer_end ~~~~~]___
                                              |<------ wait (swept) ------>|
res_ch    _________________________________________________________________[== length ==]___
ADC       _________________________________________________________________|<-off->|## readout_length ##|__ relax_delay
```

| Item | Value |
|---|---|
| Pi pulse | `qubit_ch`, `f_ge`, `pi_gain`, Gaussian sigma `sigma`, 4 sigma; flat-top (phase 0) when `flattop_length` is set |
| PMOD trigger | pin 0 at `0.01 + trig_delay - trig_buffer_start` us, width `trig_buffer_start + trig_buffer_end + 4 sigma (+ flattop_length)` |
| Wait | measured from the END of the pi pulse (`sync_all`, then `sync` on the wait register) |
| Readout | tone `pulse_freq`, `pulse_gain`, phase `res_phase`; ADC on `ro_chs`; `relax_delay` after the readout |
| Wait grid | register starts at `start` (tProc cycles; always 0) and grows by `us2cycles(T1_step)` per point; `T1_expts` points; `x_pts` is the realised wait (whole cycles), see [timing_and_units](../concepts/timing_and_units.md#register-swept-wait-axis) |

## How to run

```python
PLAN = [R.t1()]                          # regime A, values from the coherence group
PLAN = [R.t1(relax_delay=5000)]
PLAN = [R.t1(repetitions=20)]            # 20 files back to back
```

`Session(coherence=R.coherence(t1_step=5, t1_expts=100))` sets the shared group (also read
by t2_ramsey and the combos).

## Outputs

`path = "T1"`. Files under `<outerFolder>T1/T1_<date>/`:

| File | Content |
|---|---|
| `..._data_Q{qubit_readout}.h5` | `x_pts` (expts,) us; `avgi`, `avgq` (n_adc, 1, expts), winding-corrected; `qfreq` = f_ge; the fit fields below |
| `..._dataI_Data.png` | rotated (or normalised) I with the fit; title `T1 = x +- y us`, or `T1 fit not reliable` (fit drawn dashed grey if one exists) |
| `..._dataQ_Data.png` | rotated Q, no fit |
| `..._data.json` | config |
| `..._data_provenance.json` | provenance record ([architecture](../architecture.md#provenance)) |

Fit fields in the h5 (written into `data['data']` by `display`, which `finish` runs before
`save_data`; one scalar dataset each unless noted, all float64, NaN where the fit has no value).
A not-ok fit still stores its values whenever the optimiser returned some (T1 on a bound,
`T1_err >= T1`, `|a| < 3 a_err`); only a fit that never produced parameters is NaN:

| Dataset | Content |
|---|---|
| `t1_fit_ok` | 1 if the fit is reliable (see [Analysis](#analysis)), else 0 |
| `t1_fit_us`, `t1_fit_err_us` | T1 and its standard error, us |
| `t1_fit_a`, `t1_fit_c` | amplitude and offset (population units when `rotation_angle` and `min_max` are set) |
| `t1_fit_popt`, `t1_fit_perr` | (3,) `[a, T1, c]` and their standard errors |
| `t1_fit_rotation_rad` | IQ rotation applied before the fit (cfg `rotation_angle` or the automatic one) |

The same result is on the instance as `iT1.fit` (the `fit_exp_decay` dict: `ok`, `T`, `T_err`,
`a`, `c`, `popt`, `perr`, `yfit`, `T_bounds`, `error`; after an exception inside the fit only
`{'ok': False, 'error': repr(exc)}`), so a caller does not have to refit. `min_max` is carried
in the returned dict outside `data['data']` and is not saved.

## Analysis

1. Rotation: `rotation_angle` from the cfg if present, else the principal-axis phase
   (`qicklab.analysis.iq.decay_axis_phase`, closed form, no grid): the decay goes into I,
   signed so the first wait is at or above the trace mean (|e> up). The trace is multiplied by
   `exp(i * angle)` ([iq_conventions](../concepts/iq_conventions.md#3-rotations-used-by-individual-experiments)).
   Until 2026-10 the automatic angle was the phase in [0, pi] (200-point grid) minimising the
   peak-to-peak of Q, with 2-3x the angle error and an arbitrary sign.
2. Optional normalisation: if both `rotation_angle` and `min_max = [ground, excited]` are given,
   `I -> (I - ground) / (excited - ground)` and the y axis reads "Population". With `min_max`
   but no `rotation_angle` the trace stays in a.u. (until 2026-10 the fixed levels were applied
   to the data-dependent rotation, which mis-normalised).
3. Fit `a * exp(-t / T1) + c` (`qicklab.analysis.fitting.fit_exp_decay`, bounded
   `curve_fit`) with start values `a = I[0] - I[-1]`, `c = I[-1]`, and T1 = the wait where I
   is closest to `a/2.6 + c` (about the 1/e point), clipped into the bounds. Bounds from the
   sampling: T1 in `[dx/2, 20 * span]` (dx = median wait step, span = longest - shortest
   wait), `|a| <= 10 * ptp(I)`, `c` free. Reported T1 = fit T1 +- its standard error. On
   well-behaved data this is the same value as the old unbounded fit (to ~1e-5); on noisy data
   the old fit could run away (to 1e6 us and beyond), now T1 stops at the bound.
4. Reliability: `ok` is False, with the reason printed and kept in `fit['error']`, when the
   optimiser fails, the trace is degenerate (fewer than 4 points, non-finite, constant), T1
   ends on a bound (decay faster than the sampling, or not resolved within the sweep), the
   covariance is not finite, `T1_err >= T1`, or `|a| < 3 a_err` (no significant decay; on
   pure noise about 6% of fits pass the other checks without this one, under 1% with it).
   A not-ok fit is not in the title and its curve, if any, is drawn dashed grey.

`ok` is a quality flag, not an unbiased selection. Over the fits of one noisy trace the fitted
T1 is centred on the true value (median within 1-3%), but fits that overshoot T1 have the
larger `a_err` and `T1_err` and are the ones the `T1_err` and `|a|` checks drop. Simulated with
the default sweep (100 points, 0-495 us, `|a| = 1`, per-point noise sigma): at T1 <= span/2 and
sigma <= 0.15 almost every fit is ok and the ok median is within 1% of the truth; at
T1 = span, sigma = 0.15 only 87/200 are ok and their median is 0.69 T1 (0.87 at sigma 0.10); at
T1 = 2 span, sigma = 0.05, 53/200 ok, median 0.61 T1. So when building a T1(t) series from
`t1_fit_ok`, a sweep too short for the current T1 (for example after T1 drifts up) drops the
high-T1 records preferentially: keep the sweep at 3-5 T1, and check how many records were
dropped and their stored `t1_fit_us` instead of silently discarding them. The `|a|` check is
kept because without it about 6% of pure-noise traces would be flagged ok.

Assumes a single-exponential decay that reaches its floor within the sweep. Choose
`T1_step * T1_expts` of about 3-5 T1. A sweep that is too short makes `c` and T1 strongly
correlated (large `t1_fit_err_us`, or `ok` False when T1 runs into `20 * span`). The fit is
guarded inside `display`: a failed or unreliable fit never raises, the record (with
`t1_fit_ok = 0`) is saved and the repetition loop goes on
([architecture](../architecture.md#display-never-loses-the-record) covers any other display error).

## Findings & notes

- The readout window (regime-A device window) trades SNR against T1: a longer window helps
  until it exceeds about T1, after which the tail of the integration averages in decayed
  |e> population ([concepts/readout_window.md](../concepts/readout_window.md)).
- Previous CSTQ03 runner settings (history): `T1_step` 80, `T1_expts` 100, `T1_reps` 30,
  `T1_rounds` 30; `relax_delay` 5000.

## Known issues

- If the cfg has `rotation_angle = None`, display raises (`exp(1j * None)`); omit the key
  instead. (T2EMUX tolerates None.)
- The x axis is the realised wait `cycles2us(us2cycles(start) + i * us2cycles(step))`, but the
  register starts at `start` tProc cycles (not `us2cycles(start)`); correct only for
  `start = 0` (always the case from the recipe). Until 2026-10-15 the x axis was
  `start + i*step` with the unquantised step, so fitted T1 was off by -r/(1 + r), with
  r = realised/requested step - 1 (+0.02 %, too long, at `T1_step` = 5 us).
- Data are read from `[0][0]` (first ADC) although all `ro_chs` are acquired.
