# q4 fixed-frequency overnight T1 — 2026-09-30

User request: preserve the current initialization, then repeatedly measure q4
with active reset, 71 delays, and a 1500 µs maximum, using the supplied previous
q4 pulse/readout settings.

The original initialization is preserved byte-for-byte in
`docs/config_snapshots/20260930_before_q4_t1/initialize.py`, with its hash and the
requested q4 configuration alongside it. The actual initialization source and
all production TLS/active-reset files remain unchanged. The dedicated runner
never imports `Calib.initialize` or its local override. It also copies the PC's
initialization source and any `initialize.local.py` into the NAS session before
connecting, so differences on the measurement PC are recorded.

## Acquisition

```bash
git -c gc.auto=0 pull --ff-only origin tls-spectroscopy
python -u -m WorkingProjects.TLS_Spectroscopy.Client_modules.Runners.Q4RepeatedT1 --run --hours 12
```

Run after the current acquisition has finished. No YOKO commands are issued.
The qubit drive stays at 4367.760 MHz; readout is 7026.520 MHz, gain 1880,
integration 5 µs. Gaussian π gain is 32000 with sigma 2.0 µs: the existing
pulse builder makes an approximately 8 µs envelope. `qubit_length=0.25` is
retained in the requested configuration but does not control an arb Gaussian.
The fast-flux channel is 3 and stays at zero; there are no flux excursions.

Each curve has 71 logarithmically spaced delays from 1 to 1500 µs, with 1000
shots per delay. This retains the existing single-qubit T1 runner's logarithmic
spacing and 1 µs minimum. All delays are acquired once per hardware pass, then
repeated for 1000 passes, avoiding a separate long host acquisition per delay.

The existing native `opx_unbounded` reset runs after each payload readout,
preparing the following measurement. A fresh program begins with an 1800 µs
passive preroll. Runtime uses the established feedback timing (8 µs feedback
sync, 10 µs loop recovery and inter-shot gap), rather than the 1800 µs passive
wait. The legacy `reset_max_iters=3` is archived but does not cap this
confirmed-ground reset mode. The existing no-progress watchdog stops a stuck
stream; acquisition is never silently switched to passive reset.

Fresh payload and reset-loop classifiers are acquired at startup and every
30 minutes, between curves. Each reference preparation has 2000 shots and
1800 µs passive wait, honoring the q4 calibration wait rather than the shared
production helper's shorter reference default. Calibration statistics and
integer-arithmetic validation must pass; statistical failures get at most three
attempts, with every attempt saved. A transport failure stops the run.

The run stops after approximately 12 hours, finishing a curve already in
progress. `--max-runs 1` is available for a single-curve check. Each T1 displays
one progress bar with elapsed time and ETA; terminal messages are limited to
startup, SS calibration, T1 results, and errors. Ctrl+C records interruption
and stops the tProc/generators, preserving completed curves.

  telemetry. Raw IQ is written before fitting or plotting.

  linking each curve to its calibration and recording elapsed wall time.
- Invalid or rising fits are marked and excluded from the reported T1 field;
  this basic fit check is not a full scientific fit-quality assessment.
- An acquisition error stops the series. Available timeout records are saved
  separately as raw accumulator IQ; they are never treated as a complete curve.

The default 12-hour limit is an unattended repetition, not an adaptive overnight
experiment or an automation in Codex. No measurements were launched locally.
