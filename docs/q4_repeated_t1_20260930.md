## First single-curve attempt: waveform-memory failure

Session `q4_repeated_t1_20260930T075305Z_3fcf88bc` completed reset/readout
calibration but collected **zero T1 curves**. The first waveform upload failed
with `AxisSignalGen: buffer length must be 65536 samples or less.`

The existing sweep declares separate `qubit` and `qubit_reset` envelopes.
At sigma 2 µs each contains 55040 samples. Each envelope fits by itself, as
confirmed by the successful reference acquisition, but the second occupied
samples 55040 through 110079, beyond the 65536-sample generator memory.
The initial offline validation checked instruction memory and pulse duration,
but missed this cumulative waveform-address limit.

The fix is isolated to `Q4RepeatedT1.py`: its sweep subclass aliases the two
pulse names to the same memory address only after checking that their stored
I/Q arrays are exactly identical. Aliasing happens during declaration, before
reset-pulse instructions are emitted. The actual acquisition now executes the
same program object that passed preflight, using the unchanged shared DMem
transport. Every generator's addressed waveform range is checked before upload
and saved in `run_*.preflight.json`. The shared production/reset files and both
initialization files are unchanged.

Reproduction used this session's actual board configuration and actual q4
classifier with QICK 0.2.133. The original loader failed an address-plus-length
memory check at `(channel=1, address=55040, length=55040)`. The corrected loader
writes both identical envelopes at address 0; memory usage is 55040/65536.
Both versions compile to 7063 instructions. Exactly 71 compiled instructions
change: the reset waveform address is 0 instead of 3440 generator-clock units.
All other instructions and both waveform arrays are unchanged. An end-to-end
synthetic acquisition through the new path recovered 349.69 µs for a 350 µs
